Antes de rodar o script, as PRs #17 (fix de segurança — subnet pública dos nodes + security group aberto) e #18 (outputs Terraform) precisam estar merged em develop em pos_tech_fiap_terraform.

01 · arquitetura

O que sobe, e como as peças se falam

Um cluster EKS com 3 microsserviços coreografados via Amazon MQ, cada um com seu próprio datastore. Egress da VPC passa por uma NAT Instance em vez de NAT Gateway gerenciado — a principal troca de custo por manutenção deste ambiente.

04 · ordem entre repos

Por que essa sequência

Cada repo espera que o anterior já tenha rodado — não porque leem o state um do outro (não leem hoje), mas porque a nomeação de recursos e a política IAM assumem essa ordem.

pos_tech_fiap_terraform

VPC, EKS, RDS, DocumentDB, MQ, ECR, IRSA, GitHub OIDC. Base de tudo — os outros dois repos referenciam nomes que ele decide (ex: Customers-dev).

→
pos_tech_fiap_db

Tabela DynamoDB Customers-dev. Independente do EKS, mas o nome precisa bater com o que lambda_terraform espera no próximo passo.

→
pos_tech_fiap_lambda_terraform

Lambda + API Gateway. Referencia o nome da tabela DynamoDB por string — precisa que o passo anterior já tenha criado a tabela com esse nome exato.

05 · rodando o script

deploy-dev-fresh-account.sh

Roda a partir de pos_tech_fiap_terraform/scripts/, local, contra a conta AWS configurada no seu aws cli.

cd pos_tech_fiap_terraform/scripts
./deploy-dev-fresh-account.sh 50   # 50 = teto mensal em USD pro budget alert

  1. Preflight

    Confere aws, terraform e jq instalados. Mostra o account id e pede confirmação explícita — importante numa conta nova, sem rede de segurança.

  2. AWS Budget

    Cria alerta por e-mail em 80% e 100% do teto informado, antes de qualquer recurso subir.

  3. Apply pos_tech_fiap_terraform

    VPC, EKS, RDS, DocumentDB, MQ, ECR, IRSA — state local, envs/dev.tfvars.

  4. Apply pos_tech_fiap_db

    Tabela DynamoDB Customers-dev.

  5. Apply pos_tech_fiap_lambda_terraform

    Lambda JWT/Cliente + API Gateway.

  6. Consolidar outputs

    Junta os 3 terraform output -json num único outputs-dev.json.

  7. Imprimir comandos gh secret set

    Prontos pra copiar/colar se você quiser wire os workflows de CI depois — não executados automaticamente.

  8. Resumo final

    Lista o que foi criado, estimativa de custo mensal, e lembrete do comando de destroy.

06 · teardown

Desligar depois de testar

Importante

Amazon MQ e NAT Instance ficam grátis só nos primeiros 12 meses da conta e enquanto estiverem rodando — não existe modo "pausado" barato pra esse stack. Fora de sessão de teste ativa, destrua.

cd pos_tech_fiap_terraform/scripts
./destroy-dev-fresh-account.sh

Ordem reversa (lambda_terraform → db → terraform), pede confirmação digitando destroy. Depois, confira o Cost Explorer nas 24h seguintes — EIPs órfãos e snapshots automáticos às vezes sobrevivem a um destroy.
